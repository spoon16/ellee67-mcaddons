# Ender Mod

Feature id: `ender-mod`.

Kind and packs: pack feature. It is active when "ElleeDog 67 Ender Mod" (Behavior Packs) is active
in Edit World; activating it adds the core. It has no resource pack and no runtime switch. The
scripts probe `EntityTypes.get("elleedog:ender_mod_marker")` after world load to know whether the
pack is there.

## What it does

Endermen keep their native `take_block` and `place_block` goals, but both are gated behind an entity
property, `elleedog:may_move_blocks`, that the script sets every tick. An Enderman standing within four
blocks horizontally (two below, five above) of a protected coordinate is denied; one out in the
wilderness is allowed and takes, visibly carries and places blocks exactly as vanilla does. A carried
block is the real native carried block: denying an Enderman never erases what it already holds, it
only stops it from putting the block down inside a build.

Two things count as protected:

- Named areas saved with the command below. An area covers the full height of its dimension between
  two X/Z corners, boundaries inclusive, so basement and roof are both protected and so is any natural
  terrain inside it.
- Blocks players place while the pack is active. Each `playerPlaceBlock` event records the
  coordinate in a world dynamic property (one integer set per 16x16x16 section); `playerBreakBlock`
  removes it. Records survive world saves and reloads.

Every newly spawned or loaded Enderman starts denied and is re-evaluated on the following ticks. An
observed teleport (a jump of more than 1.5 blocks or a dimension change) holds the Enderman denied for
two ticks before it is evaluated again. If the store cannot be read or written the gate fails closed:
every Enderman is denied and the content log says why.

## Command

`/elleedog:ender_protect <action> ["name"]`, Admin permission, cheats not required. Actions:

| Action | What it does |
|---|---|
| `pos1` | Records the block column you stand in as the first corner (private to you, temporary). |
| `pos2` | Records the opposite corner. |
| `name "My House"` | Saves the area between your corners and clears your selection. Names are 1 to 64 characters, spaces allowed, duplicates refused. |
| `list` | Lists saved areas with their inclusive X/Z ranges and dimension. |
| `remove "My House"` | Deletes an area. Individually recorded placements stay protected. |

The command name uses an underscore: hyphens are outside every documented Bedrock identifier charset.

## The pack

`behavior_packs/elleedog67_ender_mod/` holds two entities:

- `entities/overrides/enderman.json` replaces `minecraft:enderman`. It is generated by
  `tools/codegen/enderman/inject.ts` (`npm run codegen`, or `npx tsx tools/codegen/enderman/inject.ts`
  on its own) from the pinned vanilla definition in `tools/codegen/enderman/upstream/enderman.json`:
  Mojang/bedrock-samples tag `v1.26.40.05`, `behavior_pack/entities/enderman.json`, git blob
  `23969bb19aad41238246cc9944adfe6370d0093b` (details in `tools/codegen/enderman/PROVENANCE.json`).
  The generated file differs from that snapshot in exactly three places: the
  `elleedog:may_move_blocks` property (`bool`, default `false`, not client-synced) and a
  `bool_property` filter on `minecraft:behavior.take_block` (`can_take`) and
  `minecraft:behavior.place_block` (`can_place`). When the snapshot already carries a filter the
  injector wraps it as `{ "all_of": [original, gate] }`, so a `true` property always yields vanilla
  behaviour.
- `entities/ender_mod_marker.json` defines `elleedog:ender_mod_marker`, hand-written, with
  `is_spawnable: false`, `is_summonable: false`, no components and no client entity. Nothing ever
  spawns it; it exists so the scripts can tell the pack is active.

Keep only one behavior pack that replaces `minecraft:enderman`. A competing definition removes the
property and defeats the gate; the content log reports when the script cannot find it. Put any other
Enderman pack below the ElleeDog packs or remove it.

## What off means

Ender Mod is active exactly when its pack is active; `/elleedog67:disable ender-mod` replies with the
pack to deactivate and changes nothing.

When "ElleeDog 67 Ender Mod" is deactivated in Edit World: Endermen behave like vanilla. Saved
regions are remembered and apply again when the pack is active; they and the placement records live
in the world's dynamic properties, which the pack does not own. `/elleedog:ender_protect` refuses
with "Ender Mod is not active. Ender Mod is turned on by activating "ElleeDog 67 Ender Mod"
(Behavior Packs) in Edit World." Blocks placed while the pack is not active are not recorded; put
older builds inside a named area.

## Known limits

Quoted from the upstream source README:

- "This is not exact, proven per-block protection." The gate is sampled once per tick from a nearby
  protected-coordinate query, so some natural blocks near a build are left alone as well, and that
  buffer is intentional.
- "The script cannot cancel a pickup in the same native tick as an unobserved teleport"; the order of
  property updates and native AI "needs in-game validation." Do not treat this as a zero-grief
  guarantee for valuable builds.
- "Placement lineage through pistons, falling sand/gravel, dispensers, generated growth, `/fill`,
  `/clone`, structures, or another add-on is not tracked. Enclose such builds in a named area."
- "Keep only one behavior pack that replaces `minecraft:enderman`."
- Historical blocks have no records: "Untracked does NOT prove naturally generated, it means the pack
  has no record." Stolen blocks are not restored or duplicated.
- The upstream build was validated with mocks only and has never been run in-game; the manual checks
  below are the first real evidence.

## Manual in-game checks

Use a copy of the world with "ElleeDog 67 Ender Mod" active, the Content Log enabled and no other
behavior packs that touch Endermen. Confirm `/elleedog:ender_protect` appears for an Operator with
cheats OFF and that a non-Operator cannot run it. An import notification alone is not evidence that
the script initialised; `/elleedog67:features` must read `ender-mod: active`.

1. Stand at two opposite corners of an existing build and run `pos1`, `pos2`, then
   `name "Old House"`. Run `list` and check the inclusive X/Z range and dimension.
2. Test the same area at roof, ground and basement height. Define a same-coordinate area in another
   dimension and confirm the two are independent.
3. Place a new dirt block outside every named area and confirm a nearby Enderman is denied. Break it,
   leave the vicinity, and set up a separate wilderness control site far from every tracked block and
   area. A dirt pile you build after activating the pack is tracked construction, not a natural
   control.
4. At the control site, watch native Endermen pick up and visibly carry eligible blocks. Native
   placement is rare; do not judge it from a few seconds, and do not raise the shipped chances and
   then mistake the edit for release behaviour.
5. Lead or teleport a carrying Enderman into a protected area. The block must stay in its hands and
   must not be placed there; after it leaves the buffer it should eventually place the block
   natively. Health, sounds, anger, combat and normal teleporting are otherwise vanilla.
6. Repeatedly teleport an Enderman from allowed wilderness to each edge and corner of a protected
   area, including while it carries a block, before and after a placement or a command in the same
   tick, across unload and reload, and under realistic Realm load. A missed pickup is a failed test
   and must be reported, not dismissed.
7. Confirm some natural blocks next to a build are also left alone: the buffer is intentional.
8. Run `remove "Old House"`; separate placement records must remain protected. Recreate the area and
   restart the Realm to confirm persistence.
9. Deactivate "ElleeDog 67 Ender Mod" in Edit World and reopen the world: Endermen move blocks like
   vanilla, including inside the area, `/elleedog:ender_protect` refuses with the pack hint and
   `/elleedog67:features` reads `ender-mod: packs off`. Reactivate the pack and reopen: gating
   resumes and `list` still shows "Old House".
10. Test piston and falling-block builds only inside explicitly named areas; individual block lineage
    through those mechanics is not tracked.

Record the Bedrock version, device, pack version, cheats setting, reproduction steps, exact
coordinates, expected versus actual, and any Content Log errors.
