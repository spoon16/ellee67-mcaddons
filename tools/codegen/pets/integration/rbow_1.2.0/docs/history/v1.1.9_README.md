## What the latest client feedback establishes

The user reported Lab 1 renders correctly without brandishing. Lab 2 renders
as a trident and has no brandishing (it was deliberately an inert hold-only
control). Labs 3 and 4 both render a Netherite-looking object and brandish.
Lab 5 renders the Rbow spear and brandishes, but is very low in first-person
view and displaced behind the hand/player in third person. Two user-supplied
third-person screenshots compare the Rbow weapon with the native Netherite one.

Those are **user-run observations of the old lab**, not assistant-run validation
of this update. Their provenance and qualifications are in `docs/v1.1.9_status.json`.
The absence of a difference between 3 and 4 does not prove that attachment-local
animation expressions are inactive: player-arm animation can move either model.

## The one rendering variable changed

Lab 5's local held animation used the following fixed translation:

```text
[0, 24, -27]
```

Case D and the main 1.1.9 candidate use:

```text
[0, 0, 0]
```

The third-person action-dependent jab displacement remains added to the Z
coordinate. The first-person ready/jab rotations and third-person use rotation
remain exactly the Lab 5 expressions, including their null fallbacks.

The already-working hand binding, native texture mesh, 32 x 32 held texture,
mesh rotation, pivot, scale, materials, glint, and first-/third-/non-player view
gates are unchanged from Lab 5. No per-pixel cube model, synthetic timer, custom
attack code, or player resource/animation override is introduced.

**Why test this?** The mesh is hand-bound yet visibly separated from the hand;
its fixed translation is a specific variable we can isolate. The screenshots
do not determine an exact 3D offset. Zeroing the fixed translation is a testable
hypothesis, NOT proof of a double-applied transform or a calibrated solution.
Y and Z here are model/animation coordinates, not necessarily screen up/down or
world north/south after the player's arm and item transforms are applied.

## What is preserved

Every one of the **19 existing runtime PNG files** is byte-identical to 1.1.8.
One new held-only PNG is copied byte-for-byte from the working Lab 5. Inventory
icons are unchanged. The normal longer Lab 5 mesh replaces the short ordinary
sprite in the hand; it does not replace the inventory icon or dropped-item art.

Equipment definitions, spear attack/charge mechanics, durability, reach, recipes,
ore generation, armor attachables, and runtime gameplay scripts are unchanged,
except the version printed by the read-only diagnostic. The chestplate bottom
sleeve-cap cleanup remains. Both packs retain their existing UUIDs and item IDs.

Normal drops remain ordinary Minecraft items. Placed blocks retain native blast
resistance, but loose items are not explosion-proof. Standard materials can still
be configured for trims on Rbow armor; Rbow-as-trim-material and the custom
smithing interaction remain removed. The historical load-only carrier recovery
helper and the existing armor-related player behavior override are unchanged.

## Main candidate test

Back up the world. In a disposable copy, activate **Behavior 1.1.9 and Resources
1.1.9 together**. Initially disable other item/animation resource packs.
The separate Alignment Lab is not needed to use the full Rbow add-on.

Compare a native Netherite Spear and the Rbow Spear while stationary, with the
same camera angle. Check first person, third person behind, and a side view.
Hold Use for roughly one second and release. Also test Attack separately.
The grip, framing, brandishing, jab, release, and armor-stand pose are all
**NOT RUN for this build**; do not infer success from our file tests.

## Build and verification

Python 3.10+, Pillow, Node.js 20+. No network or Minecraft executable is used.

```sh
python tools/regenerate.py
python tools/build.py
```

`tools/build_spear_alignment.py` is the sole generator for the new render chain
and the separate comparison pack. `tools/build_assets.py` continues to export
the 19 locked pre-existing textures without repainting them. Tests compare the
new held image against the original Lab 5 bytes. Source rebuilds never depend
on screenshot extraction or remote files.

The test suite checks exact runtime changes, unchanged art/combat definitions,
resolved render references, action expressions, controlled translation-only
variants, original independent lab controls, and deterministic packaging. It
**does not simulate Bedrock camera, skin skeleton, hand-binding transforms,
clipping, or native animation execution**. There are no claimed engine passes.

Superseded recovery-only assertions that required there to be no spear attachable
are preserved in `docs/retired_spear_experiments/` and replaced by explicit Lab 5
comparisons in `tests/test_119_alignment.py`. They are not reported as skipped,
passing, or proof that the former disappearance was fixed.
