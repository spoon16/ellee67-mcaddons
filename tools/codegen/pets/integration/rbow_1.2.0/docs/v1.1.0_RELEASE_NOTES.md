# 67 Rbow Ore Mod — 1.1.0 repair test build

**Author:** Ellee Schoonover — ellee@ellee.com  
**Minecraft edition:** Bedrock  
**Minimum target:** Bedrock **26.40** (`1.26.40` in the manifest), stable `@minecraft/server` **2.9.0**  
**Installer:** `67_Rbow_Ore_Mod_v1.1.0_Test.mcaddon`

This revision addresses the reported invisible/unplaceable blocks and blank/unequippable armor, and replaces the art pipeline. It is NOT yet a Minecraft- or Realm-verified resolution of all reported symptoms. The installable archive contains a behavior pack and its required resource pack. All in-game names and new identifiers use **Rbow**, including **Rbow Nug**. The original approved concept is retained only in the source archive as historical artwork; its older embedded lettering is not used as an in-game name.


## Read first: what changed and what is still pending

**Fixed in the definitions:** the three blocks used obsolete `tag:*` component keys while declaring block format `1.26.40`. Mojang removed that tag syntax for `1.26.20+` block definitions. They now use a namespaced `minecraft:tags` array. All three block items also have explicit icon-atlas entries and native block placers with matching identifiers.

**Armor repair candidate:** all four armor items now have explicit namespaced icon keys, minimal wearable definitions with the correct equipment slots, a current `1.26.30` item-format baseline, explicit armor durability chance, and trim-aware `1.20.60` attachables using documented alpha-test/glint materials. The exact cause of the armor failure on your device has NOT been confirmed from its Content Log. Do not treat static validation as proof that the client rendered or equipped it.

**New artwork:** every inventory sprite, all block faces and both worn-armor UV textures are authored from original polygon/pixel definitions. No old poster crops, Netherite masks or Netherite pixel colors are used by `tools/build_assets.py`. The approved mascot pack icon is intentionally unchanged. Inventory sprites are 32 × 32 with binary transparency; transparent pixels have zero RGB. A direct texture preview is in `art/previews/`.

**Trims implemented for testing:** Rbow armor can participate in native smithing-trim recipes using vanilla templates and vanilla trim materials. The `minecraft:trimmable_armors` tags and appropriate attachable format/materials are present. Live smithing/rendering still needs verification.

**Your additional Rbow-color request is NOT complete in this build:** a Rbow Ingot is not yet an independently functioning native trim material for diamond or other vanilla armor. Making our armor trimmable is not the same feature. No vanilla palette is replaced, no amethyst/redstone trim is silently recolored, and no existing armor is converted into substitute items. See `docs/TRIM_SUPPORT.md` for the exact scope and remaining work.

## Updating from 1.0.0 without masking the result

Back up your world first. Import this installer and confirm BOTH Behavior and Resources show **1.1.0**, not a mixed pair of releases. Fully close Minecraft and reopen it after the import. The quickest meaningful check is a new disposable Creative world with only this pair active. Take fresh copies of the seven reported items from Creative; inspect the catalog, inventory and hotbar, place all three blocks and manually drag all four armor pieces into their armor slots. Then verify worn rendering in third person. Do not use commands that force armor into slots as proof of normal equippability.

Do not delete your world, and do not load a valuable world while its custom-content packs are deactivated. Switching the pack versions in the world SETTINGS is different from loading the world without its definitions. Keep the UUIDs unchanged when updating.

## Install and test

1. Make a backup and create a **disposable copy** of your world. Do not initially activate this pack on your main Realm.
2. Open the `.mcaddon` with Bedrock on Windows, Android, or iOS. Wait for both packs to import.
3. Edit the test world. Under **Behavior Packs**, activate **67 Rbow Ore Mod — Behavior**. Under **Resource Packs**, confirm **67 Rbow Ore Mod — Resources** is active. The behavior pack declares the resource-pack dependency, but check both lists.
4. Leave Beta APIs and other experiments OFF. The manifests use stable APIs. Ordinary play does not require cheat commands. A privately distributed add-on does not qualify for Mojang's Marketplace achievement exception; keep an untouched achievement-enabled backup.
5. Open the world. Use Creative inventory search for **Rbow**, or use the explicitly optional test-kit function below in a cheats-enabled disposable world. Then verify Survival mining, crafting, combat, protection and generation.
6. After the acceptance checks pass, activate both packs on the Realm world, or upload a tested copy of the Realm world with both packs already activated. Keep everyone off the Realm while replacing the world so progress is not lost. Have joining players accept required pack downloads.

**Existing terrain is not retrofitted.** Explore beyond previously generated chunks to find newly generated ore. There is no script that fills or replaces the terrain around old builds. Keep both packs active while a world contains these custom blocks and items; removing them is not a safe conversion back to vanilla content.

### Mining, recipes and tools

Mine the ore with an **iron, diamond, netherite or Rbow pickaxe**. Properly tier-tagged third-party pickaxes are also accepted. Incorrect tools produce no ore drop. Ore normally yields one Raw Rbow Ore; Fortune increases the amount and Silk Touch yields the ore block instead. Creative breaking and disabled tile drops produce no mining loot. Custom block loot is handled by the script to preserve the pre-break tool snapshot and avoid double drops.

Smelt raw ore, or a Silk-Touched ore block, into an ingot in a furnace or blast furnace. Craft ordinary tools and armor with their familiar material patterns. Materials convert as follows:

- **1 Rbow Ingot ↔ 9 Rbow Nugs**.
- **9 Rbow Ingots ↔ 1 Rbow Block**.
- **1 Rbow Ingot + 2 vanilla sticks → 1 Rbow Spear**, diagonally, matching the native spear recipe. This is distinct from the hoe recipe.

Spear crafting grid (`I` = ingot, `S` = ordinary stick):

```text
. . I
. S .
S . .
```

Recycling one piece of equipment in a furnace/blast furnace returns one Rbow Nug. Anvils use Rbow Ingots to repair equipment; enchantment slots are configured for the corresponding gear. The axe strips recognized vanilla logs and wood, the shovel makes paths and extinguishes campfires, and the hoe tills soil and converts coarse/rooted dirt. Copper scraping/dewaxing is **not implemented in this first build**; do not assume every vanilla axe interaction is covered.

The spear uses the native `piercing_weapon` and `kinetic_weapon` components, rather than a thrown projectile or a second scripted hit. Its configured reach is 2–4.5 blocks (creative maximum 7.5), with the source Netherite spear's attack timing and charge conditions. Its custom attachable/hold pose still needs first- and third-person testing; native-equivalent jab/lunge animation is **not verified**.

### Knockback compatibility warning

**This behavior pack includes an override of `minecraft:player`.** It adds equipment sensors and a knockback-resistance component of 0.1 per worn Rbow armor piece, up to 0.4. Existing behaviors from the pinned Mojang sample are retained in the generated file.

A second behavior pack that also replaces the player definition can conflict. Pack priority alone cannot merge two different player definitions. This is a deliberate first-build compatibility tradeoff; do not assume compatibility with all Marketplace packs, or with future player-definition changes. The earlier Creeper and Ender packs used in this project target different code paths/entities, but their combined operation still requires a real-world test. Mixed native/Rbow armor and damage-driven knockback also require live verification.

## Fire and explosion protection

Placed ore and storage blocks have native `destructible_by_explosion: false` and `flammable: false`. A narrowly scoped explosion callback also removes these three block types from affected-block lists.

All 16 Rbow item definitions have native `fire_resistant: true`. A before-hurt callback cancels fire/lava and block/entity explosion damage **only when the victim is a dropped Rbow item**. It does not cancel unrelated explosions, protect players or pets, or alter vanilla item drops. Whether all native dropped-item damage paths fire the callback is a required in-game check.

**The equipment does not make its wearer fireproof or explosion-proof.** This protection is for the material/items. It does not promise immunity to the void, cactus, despawning, commands, or other packs removing items. Durability still wears through use.

## World generation

The generation rule runs only in Overworld biomes during the underground placement pass. It does not transform redstone or other ores into Rbow ore.

- **Height:** feature origins range from Y −50 to 8; each shape fits a 3-block-tall volume, keeping its placed ore between **Y −50 and 10 inclusive**.
- **Vein size:** 36 connected shapes, each containing 8–16 ore blocks, with stone and deepslate variants (72 structures total). The engine is asked to place a complete shape only where its intersection constraint accepts the host rock. Empty shape positions use structure index −1, not air. Failed placements are skipped rather than intentionally clipped to a smaller vein.
- **Host rock:** only stone or deepslate; structures do not allow replacement of existing ores, water, chests or other unsuitable blocks. All-stone/all-deepslate host constraints are conservative, including at terrain transitions.
- **Rarity:** currently **four candidate placements per chunk**, equally weighted among the 36 shapes. This is a **redstone-like encounter-frequency target, not a measured match to vanilla redstone**. Complete-shape rejection changes the realized density. It must be measured in generated terrain and tuned.

Two independently generated deposits can touch and look like a larger vein. The 8–16 count is per successful feature placement, not a global cap on all connected ore. No retroactive terrain-replacement script is included. Ore generation and structure constraints have not yet been observed running in the Minecraft engine.

### In-game acceptance checklist

1. Import with no dependency or content errors. Verify both packs and the correct mascot icons. Search Rbow in Creative inventory and place all three blocks.
2. Craft every tool and armor recipe. Confirm the hoe and spear recipes no longer collide. Check nug/ingot/block conversions and furnace/blast-furnace processing.
3. Mine both ore variants using an iron pickaxe, a wrong tool, Fortune and Silk Touch. Confirm no duplicate drops, no Creative loot, and correct final-use loot when a pickaxe breaks.
4. Compare ordinary tool and armor durability with native Netherite on the current version. Test Unbreaking, Mending, enchanting, repairing and equipment breakage. Run the diagnostic above and report mismatches.
5. Wear all armor and view it from another player and in third person. Check mixed armor, knockback, respawn, reconnect and removal of armor. Check spear hold/jab/charge visuals and damage, not just its inventory icon.
6. Test hoe tilling, shovel paths/campfires, axe stripping and retained log axis. Test cancelling/swapping an item before a delayed interaction completes.
7. Separately test Rbow blocks and dropped materials/gear with TNT, a creeper, fire and lava. Test **without 67 Creeper Mod first**, since that pack can mask creeper blast damage. Confirm nearby ordinary items and blocks still behave normally. Do not risk valuable gear until this passes.
8. Generate fresh Overworld terrain. Sample multiple chunks and seeds, count ore per height band, check complete deposit counts, and tune frequency against redstone. Check Y −51 and 11 for unintended overflow. Existing explored terrain should remain unchanged.
9. Reload the test world, then test both packs on a disposable Realm slot/copy with a second player. Review the Content Log for `[67 Rbow Ore Mod]` errors.

## Automated validation and rebuilding

`TEST_RESULTS.txt` records the actual checks run for this archive. They cover data and archive integrity, little-endian NBT structure parsing, connected shape sizes, recipe collisions, texture references, binary transparency, modern block tag rules and trim prerequisites, and JavaScript unit/mock scenarios. **They do not run Minecraft, prove native schema acceptance, or verify a Realm.** No formal full-engine schema/type validation was performed.

Requirements: Python 3.10+ with Pillow, Node.js 20+. No `npm install` is needed. To test and package the included generated files:

```bash
python3 tools/build.py
```

The optional source regeneration steps are separate:

```bash
# Pillow is sufficient; no NumPy/SciPy or vanilla image inputs are needed.
python3 tools/build_assets.py
python3 tools/build_data.py
python3 tools/build_player.py
python3 tools/build.py
```

The installer contains only the two runtime packs. The source ZIP additionally contains the original artwork, native reference images, generators, tests, documentation and test report. Tests and source generators are not executed inside Minecraft. The original approved concept is retained unchanged as provenance and is not itself a game texture.
