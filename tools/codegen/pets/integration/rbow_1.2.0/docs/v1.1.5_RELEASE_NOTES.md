# 67 Rbow Ore Mod — 1.1.5

**Author: Ellee Schoonover — ellee@ellee.com**

Native-drop and rendering cleanup, based on the shipped 1.1.4 build. This is a
client-test build: local checks run, but Minecraft/Realm acceptance is not run.
Both behavior and resource packs are version 1.1.5. Pack UUIDs, all 16 item IDs,
and all three block IDs are preserved for an in-place update.

## Changes

| Area | 1.1.5 implementation |
|---|---|
| Dropped-item explosion protection | Removed, including damage cancellation, conversion to protective entities, custom pickup/merging, rotation animations and ordinary-item polling. New dropped stacks are ordinary `minecraft:item` entities. Explosions may destroy them. |
| Placed blocks | Existing native blast resistance is retained. The redundant script explosion filter is removed. No world-wide explosion cancellation or game-rule change. |
| Ground-item behavior | Minecraft handles falling, appearance, merging, collection and despawning. No new living item carriers, extra health component or attack/hurt animation. Tools, armor and materials use the normal item renderer; the three actual blocks use block geometry. |
| Spear | Removed the faulty, offset full-length custom attachment and held texture mesh. The unchanged spear icon now uses normal `minecraft:hand_equipped` tool rendering. It will look shorter than a full-length custom model. Its recipes, native attack/kinetic components, reach, durability and damage are unchanged. |
| Deepslate inventory icon | The damaged cut-out thumbnail is removed. All three block items omit `minecraft:icon` and use their actual opaque block geometry/materials through `minecraft:block_placer`. This also avoids the flat-card appearance of dropped block items. |
| First discovery | All 14 crafting recipes use native item-discovery unlock conditions, including Raw Rbow Ore, both ore blocks, ingots, nugs, storage blocks and equipment. Minecraft owns the per-player unlock state and standard recipe notification. |
| Native trims on Rbow armor | Retained, unchanged. No Rbow-as-a-trim-material feature, workshop, UI dependency or crouch interaction. |
| Artwork | All 19 remaining runtime PNGs are byte-for-byte unchanged from 1.1.4. The four removed PNGs are the three obsolete block thumbnails and unused held-spear texture. Worn armor and equipment inventory sprites are NOT repainted. |

## Install / upgrade

Back up the local world or Realm first. Import `67_Rbow_Ore_Mod_v1.1.5.mcaddon`
and use a disposable world copy first. Verify both packs under Active:

- **67 Rbow Ore Mod — Behavior 1.1.5**
- **67 Rbow Ore Mod — Resources 1.1.5**

The behavior manifest depends on the matching resource-pack UUID/version.
Close and reopen the world after changing packs. No cheats, experimental API,
new UI dependency or automatic commands are introduced by this update.
The minimum engine remains 1.26.40 with stable `@minecraft/server` 2.9.0;
the current testing target is the user's Bedrock 26.45 release branch.

### Previously dropped items from 1.1.3/1.1.4

Collect loose Rbow equipment in the old version before upgrading when practical.
Do not remove old custom pickup entities with commands: their inventory can
contain the real equipment stack.

For items left in saved chunks, 1.1.5 includes a **load-only compatibility
importer**. It reads an old `elleedog:rbow_drop` inventory, spawns a normal item
from a full clone, clears the old slot, and removes the empty legacy entity.
This keeps the item identity/count and cloneable metadata rather than rebuilding
an undamaged item from its name. The normal dropped-item lifetime starts again
when the replacement is created.

The legacy type remains defined only so old saved inventories can be read. It
cannot be spawned from an egg or summoned, has no health/damage sensor, and has
no visible geometry. This is NOT the protective-drop system left enabled: the
pack never creates another carrier, never watches native item spawn events,
and never polls ordinary drops. The importer runs on world/chunk load, not in
a permanent per-tick pickup loop.

If spawning or clearing the old slot fails, recovery retains the old contents
and logs a warning. A failed clear rolls back the spawned copy. A double
write/rollback failure blocks automatic retries to prevent repeated copies.
Crash consistency and actual serialized-world migration still need engine
testing. Test a backup containing an old dropped item before relying on it.

Do not disable/uninstall the pack while legacy inventories remain in unvisited
chunks. Keep the backup; migration cannot run for unloaded chunks or without the
behavior pack. Ordinary native drops created in 1.1.5 no longer depend on a
custom pickup entity.

## Recipe discovery notifications

No custom toast script, action-bar substitute or inventory scan is used.
Each shaped/shapeless Rbow recipe now contains an `unlock` condition for every
Rbow item. Previously, most equipment recipes only became discoverable at the
ingot stage; now the first raw ore acquisition is also a discovery trigger.

The standard recipe toast requires the world's **Recipe Unlocking** and recipe
notifications to be enabled (`recipesUnlock` and `showRecipeMessages`). The pack
does not force either setting. Native notifications need an actual new unlock:
a player who already knows the recipes should not receive the toast again on
every pickup, and Creative is not a reliable first-discovery test.

Use a fresh Survival player/world for acceptance. Have another player place one
Raw Rbow Ore into a chest, then retrieve it with the test player, without having
previously acquired any Rbow item. Confirm the native recipe notification and
that Rbow equipment appears in the crafting-table recipe book. Recipe discovery
does not provide the crafting ingredients: raw ore still needs smelting.

All crafting inputs/outputs, ingredient counts and recipe IDs are unchanged.
The 13 furnace/blast-furnace recipes are unchanged; their processing does not
use the crafting-book notification configuration.

## Fire, explosions and normal drops

Native `minecraft:fire_resistant` remains on all Rbow items. The native component
is documented to protect dropped stacks from fire/lava. No scripted fire/damage
handler is installed. Native `minecraft:destructible_by_explosion: false` remains
on placed Rbow blocks. **Dropped Rbow equipment is not explosion-proof.**

Ordinary attacks/throwing an item should not produce the old carrier's living-
entity hurt behavior. This is not a promise that a native dropped item can never
be destroyed: explosions and other normal item-removal rules still apply.
Wearing Rbow armor does not grant the player blast immunity or prevent normal
armor durability loss. Equipment is configured with the same existing stats.

## Armor trims and compatibility

Use a standard trim template, Rbow armor piece and a standard vanilla trim
material in the normal smithing table. Rbow Ingots are not a trim material.
There are still eight Rbow armor attachables (player/nonplayer versions of each
piece); these are unchanged from 1.1.4. No vanilla armor or armor-stand override
has been added. Existing inert workshop lore may remain on older stacks.

The previously shipped `minecraft:player` override for equipment knockback is
unchanged and can still conflict with another add-on overriding the player.
Ore generation, mining scripts and recipes are otherwise preserved. Redstone-
equivalent ore frequency is still an uncalibrated target; this patch does not
change world generation or populate already-generated chunks.

| Test | Expected result; not yet run here |
|---|---|
| Native drops | Drop single ingots and two matching stacks near one another. Inspect ordinary rotation, merging, count on pickup and no custom hurt animation. Test a full inventory and a hopper. |

| Native armor trims | Use a standard template/material on each piece, then equip/view/save/reload. No custom menu should appear. |
| Upgrade | Open a backed-up 1.1.4 world with an old custom drop. Confirm exactly one native stack is recovered, with count/name/durability/enchantments intact. Revisit previously unloaded chunks. |

The optional `/scriptevent elleedog:rbow_check` diagnostic, in an appropriately
permissioned disposable test world, reports version, item/block registration,
and the two native recipe-notification rules. It is read-only and not required
to play. It does not prove client rendering.

## Source / rebuilding / evidence

`behavior_pack/` and `resource_pack/` are the actual installer contents.
`art/prismatic/textures/` contains the authoritative 19 retained PNGs, locked
against the 1.1.4 release. The review atlas combines those sprites with software
projections of the actual block faces. Projections are not Minecraft screenshots.
Historical generated posters are kept under `art/concepts/`, not shipped as
runtime textures or claimed to be exact renders.

```sh
python tools/regenerate.py
python tools/build.py
```

Prerequisites: Python 3.10+, Pillow, NumPy and Node 20+. No network or Minecraft
executable is used by these commands. The build does not include font files.
Runtime JavaScript and the small legacy-migration JSON are maintained directly.
The removed custom pickup/mesh generators cannot recreate themselves on rebuild.

Tests cover data references, opaque block textures, native render selection,
absence of drop/explosion interception, preservation of retained PNGs and armor
trim eligibility, native discovery conditions, upgrade rollback and the full
script import graph. Superseded tests requiring the removed carrier and offset
spear are replaced by removal/native-render tests, not marked as expected passes.
The old silhouette expected failure is gone because the defective deepslate
thumbnail is no longer used or included. All remaining sprite checks run normally.

**Minecraft-engine tests: 0. Client-render tests: 0. Realm tests: 0.**
