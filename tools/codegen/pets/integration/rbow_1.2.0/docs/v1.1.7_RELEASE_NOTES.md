# 67 Rbow Ore Mod — 1.1.7 Visual Repair Test

**Ellee Schoonover — ellee@ellee.com**

This build addresses two reports: a detached chestplate face below each hand,
and a spear that plays its attack/use sound but remains upright in first person.
It is based on 1.1.6. **Minecraft client/engine/Realm tests: NOT RUN.**

## Download and installation

Import `67_Rbow_Ore_Mod_v1.1.7_Visual_Repair_Test.mcaddon`. Activate both
**67 Rbow Ore Mod — Behavior 1.1.7** and **Resources 1.1.7** in a disposable
copy of the world first. UUIDs, identifiers and minimum engine/API requirements
are unchanged. Other packs that replace player or item animations can affect
the result; start with only this pack pair active.

## Chestplate sleeves

The side faces already leave the bottom three UV rows of each sleeve open.
However, the bottom cap of the arm cube was still opaque, producing a detached
rainbow face underneath the hand. Both arms share this UV rectangle (one is
mirrored), so clearing a single 8x8 region fixes the texture for both hands.

Exactly **64 pixels** in `textures/models/armor/rbow_1.png` are changed to
transparent black: `96 <= x < 104, 32 <= y < 40`. All other pixels are identical.
Sleeve length, shoulder caps, torso artwork, helmet, boots, leggings, and the
armor's geometry/attachables are unchanged. Normal native trim support remains.
The new source/runtime PNGs and artwork lock agree; regeneration retains the fix.

`art/previews/67_Rbow_Ore_Mod_v1.1.7_Sleeve_Comparison.png` is a CPU UV projection
of the actual before/after texture at an underside angle. It is not a Minecraft
screenshot and does not simulate generated native trim composites.

## First-person spear: changed rendering strategy

The user confirmed 1.1.5's short spear placement worked. They then confirmed
1.1.6's first-person motion still failed. That version modified player/rightitem
channels but left the visible weapon on the ordinary sprite rendering path.

This build adds an explicit **compact hand-bound attachable** and animates its
own `rbow_grip` bone. It uses 126 shallow pixel cubes, sampled from the unchanged
32x32 spear sprite. One source pixel is half a model unit: the icon fits within
16x16 model units before its diagonal is aligned to the shaft. This is **not**
the retired oversized `texture_meshes` model and does not restore its large
forward translation or a new texture.

The geometry is centered at the grip, with a [0,24,0] binding-space anchor.
First-person pose fitting uses the standard player arm and spear-hold frames;
those are mathematical authoring assumptions, NOT client calibration.
**The held renderer has changed, so exact screen size/hand position must be
rechecked even though the sprite and compact-size target are preserved.**

- Attack/jab: native public owner attack phase drives a visible root rotation
  and up to 1.5 model units of shaft travel through the grip, then recovery.
  It does not depend on hitting an entity, so air attacks are included.
- Use/brandish/ready: native public owner use state starts a 0.4-second readying
  motion, with later sway/lowering based on the existing kinetic weapon window.
  It is not a new damage mechanic. Release resets the local ready timer.
- FP parent attack/use channels stay at their existing idle transform for Rbow
  while the compact model supplies the local action; no doubling of the old FP
  candidate curves. All non-Rbow branches retain their vanilla values.
- Existing 1.1.6 third-person arm/wrist action curves are retained. The new model
  stays at its hand-binding anchor in third person and on armor stands; these
  contexts do not get the FP shaft slide or camera-facing rotation.
- No player resource entity replacement, new server script, input scanner,
  command, projectile, or extra damage is added.

Native owner variables still need to be supplied by the active player resource
definition. Animation packs and nonstandard character geometry can change that
or change the assumed parent pose. Safe zero fallbacks avoid invalid numbers,
but do not prove compatibility with those packs.

## What does NOT change

All sixteen item definitions, all equipment statistics, recipes/unlocks,
placed-block protection, mining/generation, and native dropped-item handling
are unchanged. There is no return of explosion-proof custom ground entities
or of the Rbow trim workshop. Ordinary trim materials can still be applied
to Rbow armor via the native smithing-table configuration.

All 18 other runtime PNGs, including the spear/icon and all inventory armor
icons, are byte-for-byte unchanged. Only the 64 sleeve-cap pixels are removed.
No item or player inventory migration is needed for these visual edits. The
existing load-only recovery helper for much older custom drops is unchanged.

## Client acceptance checks

1. Equip an untrimmed Rbow chestplate. Look at both hands from below in third
   person and on an armor stand: no colored plate should float below the hand.
   Repeat with an existing trimmed chestplate and a freshly trimmed piece.
2. In first person, tap **Attack** toward empty air, then at a reachable target.
   The spear should thrust/recover rather than only sounding. Do not confuse
   the attack control with the separate Use/ready control.
3. Hold **Use** for a second: it should lower/aim into a ready position, not
   stay upright. Release, switch slots, and switch POVs; it should return to idle.
4. Check the shaft still reaches the hand, the whole compact spear is visible,
   and third-person/armor-stand placement has not regressed. Compare a native
   spear and a normal sword to confirm their actions are unchanged.

A short recording of the separate Attack and Use actions in first person is
more useful than a still if this candidate is still wrong. Include the exact
client version, active resource packs, and any first relevant Content Log error.
Keep a backup rather than testing first on the main Realm.

## Source build and test scope

Requirements: Python 3.10+, Pillow, Node.js 20+. NumPy is used only for the
optional software-rendered sleeve comparison; no font files are bundled.

```sh
python tools/regenerate.py
python tools/build.py
# Optional actual-texture comparison:
python tools/render_sleeve_fix.py
```

`TEST_RESULTS.txt` records file/pixel/model-graph/arithmetic tests and JavaScript
API-mock tests. These are not engine tests. Test contracts that assumed the
1.1.6 absence of an attachable were updated for the new explicit model; they
were not silently skipped. New checks cover the entire image-to-model-to-
animation reference chain, hand-centered bounds, mutually exclusive views,
owner gating, motion arithmetic, use release, and exact 64-pixel sleeve change.

`docs/v1.1.7_change_scope.json` is the permitted runtime delta against 1.1.6.
`docs/v1.1.7_sleeve_fix.json` records the UV correction.
`docs/v1.1.7_spear_visual.json` records model fitting assumptions and known risks.
`docs/RELEASE_VALIDATION.json` summarizes the local checks and unrun client tests.
