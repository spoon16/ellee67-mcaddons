# 67 Rbow Ore Mod — 1.1.8 Spear Recovery

**Ellee Schoonover — ellee@ellee.com**

This release restores the ordinary held-item spear path from **1.1.5**, which
was reported to render correctly. It retains the **1.1.7 chestplate sleeve
cleanup**. **It does not fix or claim to fix spear brandishing/charge animation.**
The purpose is to recover visibility while testing the underlying rendering
problem separately rather than shipping another unverified model into gameplay.

## Files

- `67_Rbow_Ore_Mod_v1.1.8_Spear_Recovery.mcaddon`: the full Rbow gameplay add-on,
  both behavior and resource packs at 1.1.8.
- `67_Rbow_Ore_Mod_v1.1.8_Spear_Recovery_Source.zip`: full matching source,
  pinned artwork, tests, and the separate experimental Spear Lab source.
- `67_Rbow_Spear_Render_Lab_v0.1.0.mcaddon`: **optional, standalone diagnostic**,
  not part of the gameplay add-on and not required to use Rbow. Five numbered
  Creative controls; run in a new test world, not your Realm.

## Recovery install

Back up the world. Import the recovery `.mcaddon`, close/reopen Minecraft, and
confirm **Behavior 1.1.8 and Resources 1.1.8** are active together. UUIDs and
item/block identifiers are unchanged. Test in a copy before updating a Realm.
The expected recovery is the short, visible 1.1.5 held spear, with its known
animation limitation; actual rendering of this rebuilt release is still unrun.

## What changed

The 1.1.7 compact spear attachable, pixel-cube geometry, direct pose animation,
and 1.1.6/1.1.7 overrides of native player action animations are removed from
the gameplay pack. Their generators cannot recreate them. Archived copies are
under `docs/retired_spear_experiments/`, not in the installed pack.

All **19 gameplay-pack PNGs are identical to 1.1.7**, including the sleeve-cap
cleanup. Every equipment definition, recipe, ore feature, loot rule, armor
attachable, and gameplay script is unchanged except the diagnostic version text.
There is no player **resource** entity override. The existing player **behavior**
override used by Rbow armor remains as before.

Normal dropped items remain normal dropped items. Placed blocks retain their
configured explosion resistance; loose items are not explosion-proof. Fire
resistance, standard trims on Rbow armor, and recipe discovery are unchanged.
The custom trim-material workshop remains removed. No custom ground-item health,
rotation, pickup, or live protective entities are reintroduced. The existing
load-only helper for very old saved protective drops is unchanged.

## Why separate the diagnosis?

A usable item and a visible/animated item are different systems. The behavior
pack can produce a use sound and perform a kinetic attack even if its held
resource model is missing or transformed offscreen. An inventory PNG is not
proof of a correct held-model texture, and a valid geometry JSON is not proof
of a correct player-space transform.

In particular, 1.1.2 already used the published native spear geometry and pose
constants. Repeating those constants cannot honestly be called a newly proven
fix. The exact reason for the 1.1.7 disappearance remains **unconfirmed** without
client rendering or a Content Log. See `docs/SPEAR_DIAGNOSIS.md`.

## Separate laboratory

Follow `docs/SPEAR_LAB.md`. Its controls isolate these paths:

| Control | Purpose |
|---|---|
| 1 — Ordinary Sprite | Same sprite/render approach as the visible 1.1.5 spear. |
| 2 — Trident Model Control | Published native trident attachable under a custom item identifier; inert hold-only probe, no melee-spear tag or mechanics. |
| 3 — Native Mesh, Fixed Local Pose | Native spear geometry + native held texture + fixed attachment-local transforms. Native player arm animations may still move the attachment. |
| 4 — Native Mesh, Native Animation | Same mesh/texture as 3; published native spear attachment-local action expressions enabled. |
| 5 — Rbow Texture, Native Animation | Same rendering and animation as 4, changing only the held texture and test-item identity/name. |

The lab has no scripts, recipes, world generation, player override, or normal
Minecraft item/entity replacements. Its UUIDs and namespace are independent.
The Rbow held texture in control 5 is diagnostic-only, authored for the native
32px diagonal layout. It is not a repaint of the production inventory icon.

## Build

Python 3.10+, Pillow, Node.js 20+. All references are vendored; no network needed.

```sh
python tools/regenerate.py
python tools/build.py
```

Both installers and the source ZIP are written to `dist/`. The gameplay installer
contains only `behavior_pack/` and `resource_pack/`; laboratory content is never
silently activated. Local tests cover exact recovery-file differences, preserved
art and gameplay, resolved laboratory references, controlled differences between
experiments, and deterministic packaging. They do not establish Minecraft
rendering. Old tests tied to abandoned spear experiments are archived, not
counted as passing or bypassed at packaging time.

**Minecraft engine tests: 0. Client render tests: 0. Realm tests: 0.**
